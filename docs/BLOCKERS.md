# 막힌 것 · 확인 필요 · 결정 대기 (2026-10-12, 목업 v0.3 — 피드백 3라운드 반영)

## 🧭 핵심 가설

- **3차: 멈출 근거는 '정답'이 아니라 고정된 숨 주머니의 끝(꽉)이어야 감이 실력으로 남는다.** 꽉에서 놓는 비율이 10% 이상이면 틀린 가설 (미검증, [round3-breath.md](design/round3-breath.md))

- **목업의 성패는 "한 번 퍽 했을 때 손맛"으로 판가름 난다.** 아래 막힘은 대부분 그 손맛을 실기기에서 확인하지 못한 데서 온다. (미검증)
- **원작 룰 해석 두 가지가 재윤님 기억과 다를 수 있다.** 매 턴 다시 쌓기, 그림면 아래로 시작. 틀리면 조작감 전체가 바뀌니 가장 먼저 확인한다. (미검증)

## A. 재윤님 확인이 필요한 원작 룰 (기억 대조)

| # | 질문 | 목업 현재 구현 | 대안 |
|---|---|---|---|
| A1 | 한 턴이 끝난 뒤 남은 딱지를 **다시 원기둥으로 쌓았나**, 흩어진 채로 다음 사람이 불었나? | 매 턴 다시 쌓음 (턴마다 같은 '퍽' 쾌감, 읽기 쉬움) | 흩어진 채로 두기. 납작하게 깔린 딱지는 거의 안 뒤집혀서 후반이 지루해질 위험이 있다 |
| A2 | 더미를 **그림이 아래로 가게** 쌓고, 그림이 위로 오면 '뒤집힘'이었나? | 그림 아래로 시작. 뒤집히면 캐릭터가 공개되어 수집의 쾌감과 겹침 | 반대 방향 |
| A3 | 한 번에 **한 번만** 불고 상대 차례였나, 뒤집으면 한 번 더 불었나? | 한 번 불고 무조건 교대 | 뒤집으면 연속 (당구식). 실력 차가 커짐 |
| A4 | 선공은 어떻게 정했나? | 가위바위보 | 판돈 많이 건 쪽, 진 쪽 선공 등 |
| A5 | 부는 위치는 더미 **옆면**이었나, 위에서 내려 불었나? | 옆면. **4차: 누른 곳 = 바람이 닿는 곳(좌우·높이)**, 옆을 불면 반대쪽 대각선으로 굴러 넘어감 | 위에서 불기 모드 |
| A6 | 실제로 놀던 건 **종이 원형 딱지**였나, 따조·짱딱지가 섞인 기억인가? | 종이 원형 (두께 과장) | 따조형 플라스틱 질감 |
| A7 | 책상 밖으로 날아간 딱지, 모서리로 기대 선 딱지는 누구 것이었나? | **3차부터: 분필 원 밖 = 무효, 다시 쌓음** (너무 센 숨의 손해를 눈에 보이게) | 원 밖 = 상대 몫(더 가혹). 원 크기·규칙이 기억과 다르면 알려 주세요 |

> 참고: Pogs 표준 룰도 "같은 수를 내고 → 쌓고 → 앞면이 나온 것을 가져가고 → **남은 것은 다시 쌓는다**"였다 (리서치 2장, 확인). A1 의 '다시 쌓기' 해석을 뒷받침한다.

## B. 기술적으로 막힌 것 / 우회한 것

| # | 막힘 | 영향 | 우회 / 다음 |
|---|---|---|---|
| B1 | **실기기 손맛 미검증.** 이 작업 환경은 헤드리스 브라우저뿐이라 터치감, 진동, 소리, 마이크를 실제로 느껴보지 못했다 | 감도(당김 길이 = 화면 짧은 변의 42%), 슬로모 길이, 소리 볼륨이 실제로 맞는지 모름 | 재윤님 폰 플레이 피드백으로 튜닝. 수치는 `main.js` 상단 상수에 모아둠 |
| B2 | **바람은 실제 유체 시뮬레이션이 아니라 근사.** 더 세게 불수록 계속 많이 뒤집히는(단조) 성질이라, 물리만으로는 '너무 세면 손해'가 안 생긴다 | 옛 우회(조준 흔들림+상한)는 **빨강이 초록보다 더 넘어가는** 결과를 냈다 (3차 피드백, 실측 확인) | **3차 해결**: 센 숨 = 돌풍(밀어 날림) + 분필 원 밖 무효, 약한 숨 = 들썩만. `tools/powercurve.mjs` 로 초록이 최대임을 실측 |
| B3 | **claude.ai 아티팩트 뷰어는 마이크 권한을 줄 수 없다** | 공개 링크 버전에서는 '진짜 불기' 불가 | 로컬 `dist/puff.html` 에서만 마이크. 아티팩트 버전은 터치 전용 |
| B4 | **아티팩트 뷰어에서 WebAssembly(Rapier 물리) 실행 허용 여부를 이 환경에서 확인할 수 없다** | 공개 링크에서 물리 로딩이 실패할 수 있음 | 실패하면 안내 문구가 뜬다. 그때는 로컬 파일 사용. 근본 대안은 순수 JS 물리 또는 서버 시뮬레이션 |
