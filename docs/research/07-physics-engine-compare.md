# 07. 물리 엔진 비교 — Rapier ↔ Jolt (종이처럼 얇은 딱지)

- 날짜: 2026-10-16.
- 요청: 재윤님 "rust가 뭔지 또 핵심만 간략하게 설명해줘야지. jolt랑 비교 테스트해서 결정하자." 앞선 요청은 "딱지를 절반 두께로, 도화지처럼, 조금 더 통통하게"였다.
- 풀려는 문제: [`core-sweep.md`](../design/core-sweep.md) §7 '얇은 딱지 계획'.
  - 지금 물리(v1: Rapier, erp 0.2, 1/120)에 얇은 두께를 넣으면 더미가 가라앉는다.
  - erp 0.8 + 1/240 으로 바꾸면 더미는 서지만, 쏜 뒤 딱지가 멈추지 않는다.
  - 질문: 엔진을 바꾸면 이 문제가 풀리나?
- 도구: [`tools/enginecmp/`](../../tools/enginecmp/README.md). 두 엔진에 같은 API 를 씌운 어댑터, 게임 바람 이식, 실행기, 네이티브 벤치, 공정성 점검(`audit/`)이 들어 있다.
- 원자료: [`tools/enginecmp/data/`](../../tools/enginecmp/data/). `cmp-*.json.gz` 에 설정 160줄, 7,539판이 있다.
  - 전체 표: [`data/cmp-summary.md`](../../tools/enginecmp/data/cmp-summary.md)
  - 엔진별 앞선 줄: [`data/cmp-frontier.txt`](../../tools/enginecmp/data/cmp-frontier.txt)
- 계산 환경: 4코어를 다른 작업 2개와 나눠 썼다(부하 5~10). 무거운 프로세스는 늘 1개만 돌렸다. ms 숫자는 같은 부하에서 함께 잰 것끼리만 비교한다.

## 🧭 핵심 가설

**가설 (확인됨, 두께 0.055·0.04 · 기기 간 일치는 x86_64·aarch64(qemu) 까지, 실기는 미검증)**: 종이처럼 얇은 딱지를 **물리까지** 넣으려면 Jolt 로 가야 한다(자체 CPD 빌드, 하위 스텝 4, Rapier 와 같은 잠 문턱).
- Rapier 는 세 판(웹 게임 0.12 · 최신 JS 0.21 · 앱 0.36)에서 70가지 설정을 돌렸다. 그중 어디서도 '더미가 서고 + 쏜 뒤 멈춘다'를 함께 하지 못했다.
- → 재윤님이 정할 것은 엔진 이름이 아니다. **"물리까지 얇게 할까, 보이는 것만 얇게 할까"**다.
  - 물리까지 얇게 → Jolt.
  - 보이는 것만 얇게 → Rapier 그대로.

판가름 근거는 두께 0.055 의 두 숫자다. 하나는 더미 높이(명목 대비, 20장 이상 판의 최소)이고, 다른 하나는 쏜 뒤 5초 안에 완전히 멈춘 판 수(48판 중)다.

| 엔진 | 서는 설정(높이 0.9 이상) | 그중 쏜 뒤 5초 안 완전 멈춤 최대 | 멈추게 만들면 |
|---|---|---|---|
| **Jolt 5.6 (CPD)** | 10/10 | **48/48** (권고 설정. 새 시드 13~24 에서도 48/48) | — |
| Rapier JS 0.21 (최신) | 11/12 | 10/48 | 높이 0.48 (더미가 절반으로 눌림) |
| Rapier 0.36 (앱 시제품 엔진) | 24/46 | 8/48 | 높이 0.47~0.83, 또는 맨 아래 장이 책상에 0.28 u 묻힘 |
| Rapier JS 0.12 (지금 웹 게임) | 5/12 | 1/48 | 높이 0.21~0.31 |

**가설 수정 (이 보고서를 쓰면서 바뀐 것 4가지)**
1. **권고 설정을 바꿨다**: v20(속도 반복 20) → v10 + Rapier 식 잠(`jolt-fair-rsleep`).
   - v20 은 시드 1~3 만 보고 골랐다.
   - 새 시드에서는 v10 보다 못했다(37 vs 40/48).
2. **'Rapier 식 잠 문턱을 주면 Jolt 가 안 잔다'는 틀렸다.**
   - 원인은 어댑터가 잠 시간을 잘못 옮긴 것이다. 실제로는 2초가 아니라 8초 타이머였다. Jolt 는 하위 스텝을 쓰면 잠 타이머가 그만큼 느리게 간다.
   - 고쳐서 다시 재니 Jolt 는 오히려 더 좋아졌다. 두께 0.11 에서도 48/48 이 멈췄다.
3. **'두께 0.11 이면 지금 게임(v1)이 쏜 뒤 더 잘 멈춘다'는 반만 맞다.**
   - 잠 문턱을 같게 하면 Jolt 가 더 자주 완전히 멈춘다(48/48 vs 38/48).
   - 다만 판정이 나오는 시각은 v1 이 빠르다(중앙 1.56 s vs 2.71 s).
4. **'WASM 에서 Jolt 가 2~4배 빠르다'는 지금 게임의 Rapier 0.12 와 견줄 때만 맞다.**
   - 최신 Rapier 0.21 은 Jolt 보다 1.5~2배 빠르다.
   - 어느 쪽이든 45장 한 스텝이 1 ms 안팎이라 결정에 영향을 주지 않는다.

## 0. 한눈에 (결정용)

**권고 (재윤님 결정 대기)**
- **물리까지 종이처럼 얇은 딱지를 원하시면 → Jolt.** Rapier 로는 그 조합이 나오지 않는다(70가지 설정). Jolt 는 권고 설정 하나로 세 두께 모두 된다.
  - 두께를 **0.04 u(= 1 mm)** 로 하면 30장이 30 mm 로 실물과 같아진다. 이 두께에서도 47/48 이 멈춘다.
- **보이는 것만 얇아도 괜찮으시면 → Rapier 유지.** 비용이 0 이다. 대신 '눌린 더미 + 대박 아니면 꽝 분포'가 그대로 남는다.

## 1. 용어 한 줄씩 (Rust 가 뭔지)

- **Rust(러스트)**: 프로그래밍 언어다.
  - C++ 만큼 빠르다.
  - 앱을 죽게 만드는 메모리 실수를 컴파일할 때 미리 막아 준다.
  - 지금 물리 엔진 Rapier 가 Rust 로 쓰였다. 앱 시제품 물리(`native/puff_sim`)도 Rust 다.
- **Rapier(래피어)**: 지금 게임의 물리 엔진이다(Rust).
  - 웹 게임은 Rust 를 브라우저용으로 바꾼 JS 판 0.12 를 쓴다.
  - 앱 시제품은 Rust 판 0.36 을 폰에서 바로 돌린다.
- **Jolt(졸트)**: 같은 일을 하는 다른 물리 엔진이다.
  - C++ 로 쓰였다. 소니 게임 'Horizon Forbidden West' 에 쓰였다.
  - 웹에서는 같은 C++ 를 브라우저용으로 바꾼 JoltPhysics.js 를 쓴다.
- **WASM**: 브라우저가 빠르게 돌리는 기계어다. 두 엔진 모두 웹에서는 WASM 으로, 폰에서는 폰 기계어(네이티브)로 돈다.
- **결정성(같은 결과)**: 같은 입력이면 아이폰·안드로이드·웹이 소수점 마지막 자리까지 같은 결과를 내는 것이다.
  - PvP 턴 해시가 갈라지지 않으려면 꼭 필요하다.
  - 두 엔진 모두 결정성 빌드 옵션을 켜야 나온다. Rapier 는 `enhanced-determinism`, Jolt 는 `CROSS_PLATFORM_DETERMINISTIC`(이하 CPD)다.
- **하위 스텝**: 화면 한 칸(1/120초)을 더 잘게 나눠 계산하는 것이다. 얇은 딱지 더미는 두 엔진 모두 이게 있어야 선다.
- **잠**: 거의 안 움직이는 딱지를 엔진이 멈춰 세우는 것이다. '쏜 뒤 멈춤'에 크게 관여한다. 그래서 두 엔진에 같은 문턱(0.4 u/s 를 2초)을 줘야 공정하다.

## 2. 무엇을 어떻게 비교했나 (공정 조건)

- **같은 더미**: sim.js `addPile('column')` 과 같은 난수와 같은 식을 쓴다. 엔진 독립 이식은 `adapters/wind.mjs makeGamePile`, Rust 는 `puff_sim add_pile` 이다.
- **같은 샷**: 게임 바람(sim.js `applyWind` 기본 경로)을 그대로 썼다.
  - 엔진 독립 이식 `wind.mjs` 를 Rapier 0.12 위에서 돌린 결과가 진짜 sim.js 와 **48/48판 비트 동일**했다(settle·판정·6 s 해시). 공정성 점검에서 4판을 더 대조했고, 4/4 비트 동일이었다.
  - 앱 엔진(Rapier 0.36)은 앱 시제품이 실제로 쓰는 puff_sim 의 Rust 바람 코드로 쟀다. 두께만 실행 때 바꾸는 복사본(`native/puffthin`)을 만들었다.
  - 이 복사본이 기본값(게임 v1 짝)·두께 0.11 에서 sim.js 와 통계로 같은지 확인했다. 판정 중앙 1.55 vs 1.56 s, 5초 멈춤 36 vs 38/48, 뒤집힘 6.1 vs 5.4 다. 엔진 판이 달라서 비트까지 같지는 않다.
- **표준 초록 숨**: 더미 중심 앞에서, 위에서 3장째 높이로, 좌우 가운데를 분다. 물리 세기 0.95, 돌풍 0.
- **판정**: 게임 `stepJudge` 그대로다.
  - 멈춤: <0.08 u/s 가 24스텝 이어짐.
  - 느슨: 2.5 s 뒤 <0.5 u/s.
  - 상한: 5 s.
  - **완전 멈춤**은 5 s 안에 최대 속도가 0.08 u/s 아래로 내려가 6 s 끝까지 그대로인 판이다.
- **같은 물리 값**:
  - 질량이 같다(0.34558 / 0.17279 / 0.12566).
  - 마찰은 Rapier 식 평균 결합으로 맞췄다(Jolt 쪽을 맞춤).
  - 바람 가림 광선 거리가 같다.
  - 바깥 스텝은 1/120 이다. 하위 스텝 1·2·4 를 두 엔진 모두 훑었다.
  - 잠 문턱이 같다(0.4 u/s · 2 s, §7-5).

| 엔진 | 판 | 어디서 | 설정 수 (A 쌓기 · B 쏜 뒤) |
|---|---|---|---|
| Rapier JS 0.12 | `@dimforge/rapier3d-compat` 0.12.0 = 지금 웹 게임 | Node WASM | 18 · 12 |
| Rapier JS 0.21 | 최신(2026). 앱 0.36 과 같은 parry3d 0.31 세대 | Node WASM | 20 · 12 |

- 시드: A 는 1~3(Jolt 새 시드 4~9), B 는 1~12(Jolt 새 시드 13~24).

## 8. 권고와 바꾸는 비용

### 8.1 권고 (재윤님 결정 대기)

1. **물리까지 종이처럼 얇게 → Jolt (CPD 자체 빌드)**. 설정은 `jolt-fair-rsleep` 이다:
   - 하위 스텝 4(1/480), baumgarte 0.4, 속도 10·위치 4 반복
   - Jolt 기본 길이 허용치(0.02 / 0.02 / 0.2), 볼록 반경 = 반두께 × 0.5
   - 잠 0.4 u/s · 2 s(게임 시간), 밀도 1, 마찰 평균 결합
   - 두께는 0.04(1 mm, 30장 30 mm = 실물) 또는 0.055(절반). 둘 다 된다.
2. **보이는 것만 얇게 → Rapier 그대로** (core-sweep §7 ①, 지금 길). 비용이 0 이다.
   - 얇은 물리를 Rapier 로 하는 길(core-sweep §7 ② '정직한 얇은 물리는 Rust 에서만')은 이번 결과로 막혔다. 앱 엔진 Rapier 0.36 에서도 안 됐다.

| PvP | simVersion 올림 | 옛 기록과 호환이 끊긴다(친선전뿐이라 저장된 랭크는 없음) |
| 웹 번들 | gzip +150 KB (755 → 907 KB) | CPD 자체 빌드를 유지해야 한다(`native/build-jolt-cpd-wasm.sh`, emsdk 6.0.2 + glue 패치) |
| 앱 `native/puff_sim` | Rust 1,896줄 | 가장 작은 길(추정): 바람·규칙 Rust 코드는 두고, 엔진 호출만 Jolt C++ CPD 정적 라이브러리(iOS arm64·Android arm64) + C ABI 로 바꾼다. `native/jolt-bench` 가 x86_64·aarch64 CPD 빌드의 작은 증거다. parity 기준 파일(`sim_cli_shots.json`)을 다시 찍는다 |
| 앱 Dart `app/lib/native` | 2,368줄 | C ABI 를 유지하면 대부분 그대로 |
| 검증 | 실기기 해시 대조 | 지금은 qemu 만 했다. 웹 바람 Math 의 기기 간 비트는 엔진과 무관하게 필요하다 |

- **버리는 Rapier 투자**: puff_sim 의 엔진 매핑(0.18 → 0.36 parity, README '엔진 매핑'), `levels-cal` 보정표, v1 기준 원자료.
- **남는 것**: 바람 모델, `rules.js`, UI, PvP 프로토콜, Dart 장면, `detmath`.
- **덤**: Jolt 는 웹 WASM 과 앱 네이티브가 같은 엔진·같은 빌드라 **웹↔앱 대결이 된다**(확인됨, qemu). Rapier 는 지금 웹 0.12 ↔ 앱 0.36 이라, 웹↔앱 대결을 하려면 어차피 웹을 0.36 wasm 으로 바꿔야 한다.

### 8.3 단계 (Jolt 로 정하시면)

1. 웹: 깃발 뒤에서 sim.js 를 어댑터 위로 옮긴다. 먼저 Rapier v1 그대로 비트 동일을 확인하고, 그다음 Jolt 를 켠다.
2. 두께 0.04 또는 0.055 로 숨 규칙·레벨을 다시 보정한다. 재윤님이 실기기에서 손맛을 본다.
3. 앱: Jolt CPD 정적 라이브러리 + C ABI 로 puff_sim 의 엔진을 바꾼다. 웹 WASM 과 해시를 대조한다.
4. 실기기 iPhone·Android 해시 대조를 한 뒤 PvP 를 켠다.

## 9. 남은 미검증

- 실기기 iPhone·Android 해시 대조 (ARM 은 qemu 만).
- 게임 바람 JS `Math` 함수가 기기·브라우저마다 비트까지 같은지 (엔진과 무관).
- 얇은 Jolt 더미의 PvP 궤적 크기 게이트(20장 ≤ 11 KB, core-sweep §7) — 안 쟀다.
- 쓸기(blowProg)·입술 높이 경로에서의 쏜 뒤 멈춤 — 고전 표준 숨만 쟀다.
- 반발 0.2 가 실물 도화지 통통함과 맞는지 — 실물 슬로모 보정 전이다.
- 앱용 Jolt iOS·Android 정적 라이브러리, Flutter FFI — 아직 안 만들었다.
- 0.11 에서 Jolt 판정이 1.15 s 늦은 것을 사람이 느끼는지 — 손맛 미검증.
