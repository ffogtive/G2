# UI 체계 — 단추·숫자·결과 카드의 단일 출처

## 🧭 핵심 가설

**가설**: 화면이 '싸 보이는' 까닭은 그림이 아니라 문법이 여러 개라서입니다. 단추의 턱, 숫자의 그림자, 색의 뜻을 한 벌로 묶고, 결과 화면을 한 길(다음에 누를 단추 하나)로 줄이면 같은 그림으로도 비싸 보이고 '한 판 더'가 늘어납니다 (미검증) → 판가름은 재윤님 폰 전후 비교(홈·결과 카드)와 결과 화면에서 10초 안에 '같은 더미'를 누르는 비율(GDD §12.5, 목표 60% 이상)입니다.

- 근거: [`docs/research/08-clash-royale-benchmark.md`](../research/08-clash-royale-benchmark.md) A3·A5, E1~E4. 시간·색의 숫자는 캡처 관찰에서 나온 **제안값**이고, 잰 값이 아닙니다(파랑은 캡처에 값이 없어 새로 고른 값).
- 범위: 화면(`mockup/index.html` CSS · `mockup/src/main.js` 카드·HUD · `mockup/src/i18n.js`)만 바꿉니다. 물리·판정·PvP 해시는 그대로입니다(`sim src` 해시 같음, 대결 흐름 같음).
- 이 문서가 값의 단일 출처입니다. **값은 `mockup/index.html` 맨 위 `:root` 토큰 한 곳에만 있습니다.** 값을 바꾸면 이 표도 같이 고칩니다.

### 못 누르는 상태 네 가지

모양은 그대로 두고 색만 바꿉니다. 화면마다 왜 못 누르는지가 달라서 네 가지로 나눕니다.

| 상태 | 보이는 것 | 클래스 | 지금 쓰는 곳 |
|---|---|---|---|
| ① 조건이 안 됨 | 같은 모양의 회색(`#d6d6d6` / `#b4b4b4` / `#868686`) | `:disabled` · `.is-off` | 오늘의 더미 '다시 불기'(기회를 다 씀) |
| ② 잠김 | 밝기 50% | `.is-locked` | (홈 잠금, 08 A8 — 결정 뒤) |
| ③ 비용 부족 | 흑백 | `.is-poor` | (숨 풍선, 08 A10 — 결정 뒤) |
| ④ 아직 없음 | 흑백 + 여는 조건 한 줄(`data-cond`) | `.is-soon` | (홈 잠금, 08 A8 — 결정 뒤) |

## 숫자

| 부분 | 값 | 토큰 |
|---|---|---|
| 글자 | 흰색 · 고정폭 숫자 | `.num` |
| 테두리 | 얇게 0.06em (그릴 때 2배 두께 + `paint-order` 로 바깥 절반만 보임) | `--ui-stroke` |
| 그림자 | 아래로만, 흐림 없이 `0 .16em 0 #111` | `--ui-drop` · `--ui-ink` |
| 늘어난 값 | 초록 `#3ae449` 으로 '+N' | `--ui-plus` · `.num.plus` · `.float.plus` |

쓰는 곳: HUD 점수·가운데 상자, 쓸기 결과 카드의 뒤집힌 장수, 떠오르는 '+N', 레벨 결과 숫자(`#lrDetail`), 대결 결과 점수·늘어난 딱지(+N), 오늘의 더미 점수. 제목·배너·가운데 큰 글자(`.big`·`.banner`·로고)는 아직 예전 굵은 외곽선입니다(다음 조각에서 정함).

## 결과 카드 (쓸기 연습판)

한 길만 남깁니다. 다음에 누를 것이 하나로 보여야 '한 판 더'가 빨라진다는 가설입니다.

```
[ 38/40 뒤집힘 · 책상 밖 1          ★ ★ ★ ]   ← 장수(큰 흰 숫자) + D 박자 별(①②③ 자리)
[ 👍 좋아요                         ▸ 자세히 ]   ← 원인 하나(가장 나쁜 박자) · 자세히 = 접힘
[ 새 더미 ]  [    같은 더미    ]  [ 홈 ]          ← 보조 · 노랑 주 단추(맨 끝에 나옴) · 보조
```

- '같은 더미'(노랑 주 단추)는 연출이 끝날 때 나옵니다. '새 더미'와 '홈'은 처음부터 보이는 작은 파랑 보조 단추입니다(먼저 나가고 싶은 사람을 막지 않음).
- 개발 이름표는 첫 화면에서 뺐습니다. '방금 숨 · 세 박자/주입'과 비교 토글 조합 글은 '자세히' 안 첫 줄, 타임라인·숫자도 '자세히' 안입니다(D 는 늘 접힌 채로 시작).
- '기록 복사'는 ⚙ 맨 위 쓸기 칸의 '쓸기 기록 복사'로 옮겼습니다. 이번 실행 기록이 없으면 ① 조건이 안 됨(회색)입니다.
- 박자 별은 문법 D 에만 있습니다(C·B·A 는 박자가 없어 별 줄 없음, 칩은 예전 그대로).

## 결과 연출

모든 값과 글은 카드가 뜰 때 이미 들어 있고, 연출은 보이는 때만 늦춥니다(시험·자세히가 바로 읽음). 시각은 `main.js` `SW_RV` 한 곳에 있습니다.

| 차례 | 카드가 뜬 뒤 | 내용 |
|---|---|---|
| ① 세어 올리기 | 0 → 최대 0.8 s | 뒤집힌 장수를 0 부터 셉니다(250 ms + 장당 15 ms, 0.8 s 상한, 끝이 느려지는 곡선) |
| ② 별 | +150 ms 부터 | 초록 박자마다 별 하나: 350 ms(1.1배 → 1.0배, 흰 번쩍) · 별 사이 250 ms · 진동 24 ms(앱 다리 16~32 ms = iOS `tapMedium`) · 동전 소리 |
| ③ 원인 | 마지막 별 끝 + 150 ms | 칩 하나(가장 나쁜 박자, `Sweep.gdChip`) |
| ④ 같은 더미 | 칩 + 300 ms | 0 → 1.08 → 1 배로 커지며 나옴(300 ms) |

예: 40장 38장 · 세 박자 모두 초록 = 세어 올리기 800 · 별 950 / 1550 / 2150 · 칩 2650 · 단추 2950 ms.

- 카드 빈 곳을 톡 하면 끝 상태로 건너뜁니다(남은 별 진동 없음).
- 기기 설정 '동작 줄이기'(`prefers-reduced-motion`)면 처음부터 끝 상태입니다.
- 진동은 기존 게임 진동 길(`navigator.vibrate` → 앱 다리 `g:auto:…:24` → Core Haptics `tapMedium`)을 그대로 씁니다. 별 진동 값 24 는 쓸기 진동(35·25·20·12)과 달라 진동 기록에서 갈립니다.
